What changed, and why

Destructive status changes now explain their cost

Was

The operator could select Deactivate user and immediately start the cleanup mutation without a second look at who would be affected.

Now

The existing mutation waits behind the shared danger confirmation. Cancel closes the prompt without changing status; confirm keeps the existing server-side custody, cleanup, permission, and audit behavior.

Copy actions now tell the truth

Was

Selected copy controls relied on direct browser writes, so denied or unavailable clipboard access could leave the operator without a useful outcome or recovery instruction.

Now

A shared helper reports success only after the browser write resolves. Failure shows a short manual-copy instruction while the visible value remains available across kiosk codes, guide references, calendar feeds, and item identity controls.

Rapid repeats no longer shorten or scramble feedback

Was

Every successful item or guide copy started an independent timer. A first timer could clear a later success early, and a slow older clipboard result could replace the latest clicked identity value.

Now

The latest attempt owns the visible copied state. A repeat success cancels the older timer and receives the full display window; superseded promises are ignored and timers are cleared when the control leaves the page.
