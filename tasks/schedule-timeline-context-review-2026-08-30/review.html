What changed, and why

A stress-test week leaked into List

Was

Entering List from a standalone Week or Calendar period could land on Sep. 21 instead of the current day.

Now

Standalone period-to-List navigation clears period reading anchors and goes to Today; only a genuine List-origin round trip restores the earlier List place.

Rapid view toggles could rehydrate stale URL state

Was

A fast Week → Calendar → Week sequence could let an older router update replace the user's newer period choice.

Now

The active period is handed between views immediately and owned URL writes are recognized before the router round trip, with filters retained.

Week compressed the work into fragments

Was

Small cards truncated event identity and hid useful coverage, open-slot, venue, and personal-shift context.

Now

The shared period header, day counts, readable event cards, explicit staffing state, and expanded mobile days make Week independently useful.

Calendar stopped working on phones

Was

Phone widths replaced the month with a recommendation to switch views.

Now

Calendar keeps the desktop grid and adds a complete active-day mobile agenda with matching event, coverage, and open-slot semantics.

Scope changes could show the wrong rows

Was

A server-backed view or sport change could temporarily display prior-scope events under newly selected controls.

Now

Only compatible older-record expansion keeps existing rows; every other scope uses an honest geometry-preserving loading state.

Week and Calendar stopped at read-only context

Was

Configured events opened the legacy detail panel and unconfigured events navigated away, so staff could not complete the List crew workflow from either period view.

Now

All three views use one focused staff sheet backed by the existing versioned editor. Unconfigured events offer Home, Away, or empty setup; List keeps its inline multi-event workstation as well.
