What changed, and why

Capture had a second workflow after commit

Was

A player save opened a website-profile form, while the roster kept warning that a profile was needed.

Now

A committed save changes the action to Saved with a restrained check animation, then replaces the capture history entry with the roster.

Profile data leaked into the capture contract

Was

Detail and bootstrap responses exposed profile completeness and fields, and a Signatures-only mutation route could update them.

Now

The UI, response fields, mutation route, service, validation schema, and permission are removed. Existing database columns remain dormant and untouched.

A post-commit navigation failure could lie

Was

An exception after commit could fall into generic save-failure feedback.

Now

Committed state remains Saved, repeat save is disabled, and the operator gets a truthful manual roster-return message.

Things to know

  • The save animation was not triggered against live roster data because that would replace a real private signature artifact. Its state ordering, reduced-motion timing, direct roster navigation, and post-commit failure fallback are covered by focused source contracts; physical iPad and Apple Pencil acceptance remains open.
