What changed, and why

This is a presentation-only slice. The API payload, owner allowlist, privacy boundary, and build-comparison semantics stay unchanged.

Web activity was repeated per installation

Was

A user with many web installation keys produced a very tall row full of repeated Browser client entries, making the row's useful signals hard to scan.

Now

The Latest browser column shows the most recently seen web client and the total installation count.

iOS context was split across ambiguous columns

Was

Clients and device mixed web and iOS hardware, while Build / channel omitted the iOS OS version and required scanning across repeated blocks.

Now

iOS hardware lists distinct reported models; iOS software keeps OS version, marketing version, build, freshness status, and release channel together for each iOS client.

Desktop density hid the final context column

Was

The table's content width pushed Last seen just beyond the normal desktop surface after adding the new support signal columns.

Now

Tighter minimums and wrapped user metadata keep all six headers visible at desktop width; the shared table container still scrolls intentionally at narrow widths.

Verification

  • Focused source contracts: App Activity UI and brand-identity tests pass.
  • TypeScript: npx tsc --noEmit --pretty false passes.
  • Lint: npm run lint passes.
  • Production-shaped build: npm run build:app passes.
  • Authenticated browser: owner-gated local preview renders the six headers, two iOS clients, and summarized browser activity.
  • Narrow viewport: the table reports overflow-x: auto with 999px content inside a 563px viewport, preserving access without clipping.

Things to know

  • No production deployment was made for this UI slice; the live production page remains unchanged until the implementation is explicitly shipped.
  • The telemetry identifies a web client, not the browser engine. The label stays Browser client rather than inferring Chrome or Safari.
