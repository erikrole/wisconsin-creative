What changed, and why

This slice closes the two native notification findings that shared an existing server contract; it does not claim APNs delivery or physical-device acceptance.

Account pause is now visible and reversible

Was

A future pausedUntil value was silently ignored, so the native screen could promise enabled delivery while the server suppressed push and email.

Now

Quiet hours shows the active end time, exposes Pause 1 hour/day/week when clear, and gives a one-tap Resume now action. The in-app inbox remains explicitly available.

The device self-test follows ordinary delivery eligibility

Was

The test button appeared whenever iOS allowed push and a token string existed, even when the account was paused, Push alerts were off, or APNs registration had failed.

Now

The test requires Push alerts on, no active pause, iOS authorization, a server-accepted registration, and the current installation token; otherwise the screen names the next recovery action.

Preference failures are no longer silent

Was

A failed toggle save reverted the optimistic switch and stored an error, but the loaded settings screen never rendered or announced that error.

Now

Loaded save errors render inline with Reload, announce through VoiceOver, and clear before the next save attempt while preserving the safe revert.

Things to know

  • This is deterministic fixture proof, not authenticated production proof. Real APNs delivery, notification permission changes, and physical-device acceptance remain separate gates.
  • The baseline and after captures were run at different wall-clock minutes, so the simulator clock differs; preference data, device, fixture, and UI actions were held constant.
  • Account deletion remains parked until the product accepts the historical-custody and erasure/pseudonymization contract documented in the remediation plan.
