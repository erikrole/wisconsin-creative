What changed, and why

Return record was easy to miss

Was

A small percentage shared the same weight as several adjacent time statistics, and sparse history appeared as an unexplained dash.

Now

The percentage is larger, carries its completed-return sample, and adds a rate-length bar whose fill is full red at 50% and below, continuously interpolates, and reaches full green at 100%. Sparse history says Not rated.

The row mixed summaries with diagnostics

Was

Active overdue, total late, worst late, typical late, checkout count, on-time rate, and last incident were distributed across eight columns plus one crowded subline.

Now

Late events owns the active-overdue state; late-time pattern owns total, typical, and worst; return record owns percentage and completed returns.

Every row acted like a button around real links

Was

The table row and mobile card were keyboard/click targets while also containing profile, checkout, and ADMIN action controls.

Now

Profile links and actions remain independent siblings, and one labeled 40px button owns expansion with aria-expanded and aria-controls.

Receipts were split across table columns

Was

Booking title, due context, late duration, return state, and cleanup action were separated by the parent table grid.

Now

One incident-history region groups each booking and all of its evidence into a complete readable record.

The fun stays purposeful

Was

Dense evidence risked competing with the playful wrong-leaderboard framing.

Now

The stable shared jeers remain in the top-three spotlight; the full ranking stays calm, with the escape-route copy pointing people back to the return record.

Verification

  • Focused contracts: 65 Accountability, jeer, route, service, RBAC, search, sidebar, and UI tests pass.
  • Static/build: TypeScript, focused ESLint, codemap/docs verification, whitespace check, and the 238-page build:app pass. The build ran from an isolated temporary copy so it could not disturb the shared dev server's .next directory.
  • Authenticated browser: The same nine-person board renders at 1440×1000 and 1024×900 with zero document overflow and no console warnings or errors.
  • Measured interaction: The desktop history button is 110×40px, exposes aria-expanded/aria-controls, and opens one 294px incident region containing four checkout links and four ADMIN action controls for the first person.
  • Color read-back: Live bars resolve to red/green mixes of 74/26 at 63%, 62/38 at 69%, 50/50 at 75%, and 36/64 at 82%; the source clamps 50% to all red and 100% to all green.
