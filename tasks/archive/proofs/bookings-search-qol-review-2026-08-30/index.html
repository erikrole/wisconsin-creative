What changed, and why

Opening a booking lost list context

Was

Pagination lived only in component state, URL rehydration reset the page, and card/table preference was not part of browser history.

Now

The complete list context is serialized through App Router replacement navigation and rehydrates on browser Back. Clear all also clears the search query.

Reservation creation depended on the selected tab

Was

The action lived inside reservation-list rendering and disappeared in other Bookings contexts.

Now

One permission-aware New reservation action stays in the Bookings page header across tabs and active/past scope.

Search failures were a dead end

Was

Complete and partial failures explained the problem but offered no direct retry; a failed refresh could also discard a previously healthy result group.

Now

Complete and partial failure states offer Retry. Same-query rows from a failed source remain visible until that source successfully refreshes, while a new query never inherits stale rows.
