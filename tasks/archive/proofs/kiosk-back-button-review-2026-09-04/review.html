What changed, and why

The shell no longer intercepts flow navigation

Was

A global device-status button was positioned at top-leading for every active screen, directly underneath the flow header's Back/Cancel control.

Now

The status reveal is rendered only for idle and success; operator hub, identity, checkout, pickup, and return leave the top-left target to their own flow navigation.

The status affordance remains available where it is safe

Was

Removing the collision could have hidden a useful kiosk diagnostic affordance entirely.

Now

Idle and success retain the existing Show device status control, while flow screens avoid a second action in a navigation-critical corner.

  • Native gates: WisconsinKiosk Debug and Release builds pass for the iPad Air 11-inch (M4), iOS 26.5 simulator; project parity, drift, iOS gap audits, and diff checks pass.

Things to know

  • This is local source/build/simulator proof only. The shell status reveal remains intentionally available on idle and success; no custody, API, schema, permission, or scanner semantics changed.
  • Managed-iPad interaction and deployment remain separate release gates.
