What changed, and why

Direct B&H search

Was

No external product-search shortcut.

Now

A prefilled editable query opens B&H in a separate tab, including when the API provider is unavailable.

Trustworthy pasted photo

Was

Protected B&H links could fail previews; selection could precede image load.

Now

B&H image links use the static host, selection waits for a loaded preview, and product links get recovery guidance.

Verification

  • 84 focused tests passed; TypeScript, scoped lint, and application build passed.
  • Actual shared image picker exercised in Chromium at 1280, 768 and 390px; no page errors.
  • Fixture checked query encoding, empty-query disablement, product-page recovery, and selected normalized image URL.
  • Authenticated isolated ADMIN preview at 1280 and 768px loaded a live static B&H image, staged it, and removed it; no inventory writes or page errors. Equivalent pasted B&H links retain preview readiness.

Things to know

  • No inventory mutations or deployment. B&H product-page HTML is not fetched; use the photo address or upload.
  • Matched captures precede the final equivalent-URL readiness fix, which does not change presentation; the authenticated check exercises the final source.
