Schedule UI polish after the trust pass

Staff and students should read one honest row for combined events, see every area they work, and never confuse a failed Trade Board count or a private crew edit with an empty board.

After-only

No trustworthy matched pair. The checkout already carried the Schedule trust-pass dirty tree, no isolated baseline was captured before this polish, and WisconsinPerformance ScheduleScreenshotUITests crashed at bootstrap (signal term) on iPhone 16 Pro iOS 27.0.

What changed, and why

Claim pause spoke on every open slot

Was

Each empty Student slot repeated “Staff are updating this crew,” so a six-slot crew looked like six problems.

Now

One crew-level notice on Schedule disclosure and Event detail. Claim buttons stay hidden until the draft releases.

Combined events were silent on native rows

Was

Web named “N events · shared crew.” iOS collapsed the row but did not say why two games shared one crew.

Now

Native list and Event detail use the same shared-crew cue. Web mobile list and timed multi-day rows also name the span.

A second personal area disappeared

Was

Dictionary uniquing kept only the earliest shift, so Photo vanished when Camera was also assigned.

Now

The list names every extra area. Event detail lists each personal assignment.

Publish now sat under history controls

Was

Undo, Redo, and Revert led the pending card; Publish now was the last button. Ended drafts still advertised the 10-minute timer.

Now

Publish now / Apply correction now is the primary action. Ended pending copies omit the timer copy.

A failed Trade Board count looked like zero trades

Was

A non-OK fetch returned 0 and overwrote a known count in the React Query cache.

Now

The count fetch throws, so a failure keeps the last good number and does not show a 0 badge.
