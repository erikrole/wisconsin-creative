What changed, and why

Fixed copy became a shared deck

Was

Each podium rank had one hard-coded sentence, so repeat visits quickly felt familiar.

Now

The API returns three unique lines from a reviewed 50-line source deck alongside the leaderboard.

Random does not mean inconsistent

Was

Per-viewer or per-render randomness would let people see different jokes and would churn on refresh.

Now

A deterministic seeded shuffle uses the ordered leaderboard fingerprint, producing the same deal for every internal role and render environment.

The joke waits for new material

Was

A background refresh or continuously increasing late-hours value could have changed copy without a real leaderboard event.

Now

The fingerprint ignores clock-only hour drift and changes for membership, ranking order, active state, late-event count, active-overdue count, or last incident.

No runtime AI dependency

Was

Generating copy on demand would add latency, cost, and unpredictable output to a simple report read.

Now

Luna Max generated the reviewed source deck once; serving and rotating it is local, bounded, and deterministic.

Verification

  • Focused contracts: 64 Accountability, deck, route, service, RBAC, search, sidebar, and UI tests pass.
  • Static/build: TypeScript, focused ESLint, docs/codemap verification, whitespace check, and the 238-page build:app pass.
  • Shared API contract: ADMIN, STAFF, and STUDENT receive the same three unique jeers for identical leaderboard input; unchanged cloned input returns the same draw.
  • Authenticated browser: Volume reloads retained the exact same three lines. Time changed leaderboard order and produced a distinct three-line set; returning to Volume restored the original set.
  • Responsive render: 1440×1000 and 1024×900 show all three lines with zero horizontal overflow and no console warnings or errors.

Things to know

  • The selector guarantees no duplicate within a served set. Future distinct leaderboard states can eventually revisit a line because the product does not keep a durable history of every prior draw.
  • Clock-only total-late-hours movement is excluded from the seed, but a Time-sort order change still rotates the set because ordered rank is part of the fingerprint.
  • There is no runtime model call, browser storage, per-user seed, database write, or deployment in this slice.
