What changed, and why

Future custody was hidden by default

Was

The resting list filtered the complete dashboard response down to today and overdue, so staff had to tap Checkouts to discover gear due later.

Now

The resting list consumes every active checkout and keeps the existing due-time chips and earliest-due-first ordering.

The Checkouts toggle would become a no-op

Was

Using the old toggle model with the new default would claim to clear a filter while rendering the same rows.

Now

Checkouts is the explicit resting selection. Items Out and Overdue temporarily narrow the rail and return to all checkouts when cleared.

Layout and payload order disagreed with the default

Was

The selected Checkouts tile sat between two other filters, and the view trusted whatever row order arrived from the server or fixture.

Now

Checkouts is first, and the native view guarantees overdue-first then earliest-due ordering with a stable title tie-breaker.
