What changed, and why

Upcoming demand was treated as a categorical stop

Was

Any future serialized booking hid Extend for an open checkout, even when hours of conflict-free time remained.

Now

Upcoming demand constrains the selected return time. The checkout can extend up to the next booking's actual start.

The safety boundary remains authoritative

Was

The shared 60-minute serialized buffer blocked the extension before a real overlap existed.

Now

Only this open-checkout extension path uses overlap-only serialized checks. Bulk shortages, true overlaps, optimistic freshness, serializable writes, audit history, and database overlap protection remain enforced.
