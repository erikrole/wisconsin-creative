What changed, and why

Eight routes carry less startup JavaScript

Was

The shared shell eagerly included optional profile form and badge code.

Now

On-demand loading lowers initial gzip bytes by / 9.4%; /items 6.6%; /bookings 6.9%; /schedule 3.6%; /reservations/new 3.9%; /users 7.7%; /resources 6.6%; /signatures 4.7%. These are build measurements, not page-load latency.

One page mount through cache restoration

Was

The provider changed type after mounting. Cold and corrupt-cache fixtures issued two query requests and two effect requests.

Now

One mount and one of each request. A fresh persisted dashboard needs zero query requests. Denied storage safely uses memory. All 20 browser trials passed.

Native rows share thumbnail work

Was

24 simultaneous cold-cache consumers created 24 requests and 24 decoded images in the fixture.

Now

One request and one shared image. Tests cover size/scale, one-row and all-row cancellation, retry, and sign-out isolation. This is a request/allocation reduction, not a physical-device scrolling claim.

API decoding leaves the UI thread

Was

Median synchronous decoding occupied the main actor for 0.259 ms at 30 assets, 2.457 ms at 300, and 23.967 ms at the 3,000-row stress size.

Now

Thread-probe tests confirm off-main decoding. Total medians are 0.296 / 2.590 / 25.290 ms; overall CPU work is not reduced. The client rechecks account ownership and cancellation before publication.

Broad native measurements are stable

Was

Median Debug simulator launch 2.212 s; Items CPU 1.028 s; equipment CPU 0.931 s.

Now

Launch 2.166 s; Items CPU 1.020 s; equipment CPU 0.944 s. Ranges overlap. No broad launch/scroll improvement is claimed; these fixtures bypass the optimized decoding and images.
