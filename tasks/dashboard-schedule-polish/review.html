What changed, and why

Both surfaces were already conforming on structure, color, and targets. These are cascade defects that no structural audit would surface.

Every var(--font-mono) in the app was rendering sans

Was

--font-mono is declared on :root and resolves --font-geist-mono, which next/font defines only where its variable class is applied. That class sat on <body>, one level below :root, so the token computed to empty. Measured: --font-mono at :root returned nothing and a probe element resolved to ui-sans-serif.

Now

Both font variable classes moved to <html>. The same probe now resolves GeistMono. This reaches 25 call sites across 12 files — dashboard flagged items and lost bulk units, schedule list times, item asset tags, booking references, and server paths.

Eight heading declarations did nothing

Was

The typography block in globals.css is unlayered, so it outranks every Tailwind utility. A text-sm font-semibold on an h2 rendered at 18px/800, not 13px/600.

Now

All eight carry the important modifier. The two schedule cases matter most: the automation digest and the ListView day-group label were authored as quiet 13px labels and were rendering as prominent headings in a surface the design language explicitly wants dense.

Twelve icon controls, one real problem

Was

The audit flagged twelve icon buttons under 40px. Eleven already pinned size-10 and merely carried a redundant size="icon" prop that tailwind-merge discards.

Now

The eleven dead props are gone. The one real violation — the open-slot remove control in AssignmentCell at size-7, 28px — is now 40px.

Verification

  • TypeScript: clean. Lint: clean across src/app, src/components, and tests.
  • Full suite: 3619 passing, 0 failing, 537 files.
  • Build: npm run build:app compiles. Docs: codemaps current.
  • New contract test: tests/typography-scope-source.test.ts, 4 assertions pinning the font variables to <html>, the mono token, the important modifiers, and the absence of inert heading utilities on both surfaces.
  • Font fix measured, not inferred: computed font-family read from a probe element before and after — ui-sans-serif then GeistMono — and --font-geist-mono traced to confirm it was in scope on <body> but not :root.
  • Baseline method: git stash push scoped to src/app/layout.tsx alone, so nothing else differed between capture runs. Restore verified.

What this does not prove

  • Neither route was captured directly. / and /schedule both require an authenticated session, the standing local limitation. The harness renders the same declarations and the same monospace content, but not the real pages with real data.
  • The font change is app-wide, not scoped to these two routes. It affects all 25 var(--font-mono) call sites. That is the correct fix — the token was simply broken — but only the dashboard and schedule patterns were visually reviewed.
  • Unverified interactions: no filter, view toggle, calendar navigation, or crew editing was driven. The heading and font changes are presentational and no logic was touched, but the surfaces were not exercised.
  • Still open, unchanged: the underlying fix is to move the typography block into @layer base so utilities work normally without the important modifier. It changes 141 headings at once and remains queued as its own slice.
  • Also open: there are no font-heading or font-mono Tailwind utilities, which is why 24 inline fontFamily styles remain on these two surfaces. Adding font entries to @theme inline would let those become classes.
